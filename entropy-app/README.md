# Локальний кабінет Entropy

У готовому архіві відкрийте **START.html** у звичайному браузері. Це самостійний файл: встановлювати залежності для цього не потрібно. Дані й рішення зберігаються лише в браузері; для перенесення використовуйте «Зберегти копію».

Нижче — опис вихідного проєкту й запуску для розробника.

# Entropy Contributors

Локальний прототип закритого кабінету для перегляду кріейторів Entropy, оцінювання їхнього внеску й ручної модерації.

Актуальна хмарна версія розміщена в сусідньому `entropy-cloud`; цей каталог є спільним джерелом моделі й інтерфейсу. `relevance.mjs` перевіряє також твіти без @entropyIO за офіційними URL, цитатами й характерним контекстом продукту. Неоднозначні назви не враховуються до підтвердження в приватній «Перевірці згадок». Рішення з причинами зберігаються за Post ID; реплай не стає придатним після підтвердження контексту. Є явна перевірка пропущеного поста за посиланням. Погодинний збір і три незалежні черги описані в `entropy-cloud/OPERATIONS.md`.

## Запуск

У каталозі `entropy-app` виконайте:

```sh
node serve.mjs
```

Відкрийте [локальний кабінет](http://127.0.0.1:8767). Сервер слухає лише цей комп’ютер. Щоб зупинити його, натисніть `Ctrl+C` у вікні запуску.

## Дані першого запуску

`seed.json` містить **24 пости дев’яти авторів** за 17 жовтня — 16 листопада 2026 року. Це часткова дослідницька вибірка, вручну звірена на сторінках X станом на 17 листопада 2026 року.

Це історичний знімок. Постійне сканування X і оновлення метрик не підключені. Для обраного провайдера twitterapi.io додано серверний адаптер та обмежений ручний збирач; див. [опис підключення](TWITTERAPI.md).

- Покази, лайки й доступні коментарі — накопичені лічильники на дату перевірки. Це не метрики за перші 72 години.
- Сума показів постів не означає кількість унікальних людей.
- Повноту внеску кожного автора за місяць не встановлено.
- Для постів збережені відомі дати, короткі описи та посилання на оригінал. Точний час і повний текст не додумані: `publishedAt` і `body` дорівнюють `null`.
- Локальні ID авторів мають вигляд `sample:<handle>`. Це не справжні X User ID. ID постів збережені точними текстовими рядками.
- Видимий у X лічильник репостів збережений як `uiReposts`. Він не підставляється замість API `retweet_count`: поля `reposts` і `quotes` поки невідомі.
- `null` означає невідоме значення. Число `0` означає зафіксований нуль.

## Рейтинг і модерація

Основний перегляд — автори за сумою показів врахованих постів. Окремі метрики та Score допомагають порівнювати внесок за іншими критеріями.

Ручні рішення стосуються участі у нашому рейтингу:

- **Виключення поста:** його внесок прибирається з розрахунку.
- **Незарахування автора за період:** автор не бере участі в цьому відборі.
- **Бан автора:** автор не бере участі в рейтингах до ручного скасування бану.

Для виключення або бану потрібна причина, яку можна показати кріейтору. Перегляд цієї причини в локальному кабінеті є попереднім переглядом, а не опублікованою сторінкою чи надісланим повідомленням. Дії не змінюють акаунти та пости в X.

Локальний стан рішень зберігається в браузері. Інший браузер не отримує ці рішення автоматично; очищення даних браузера може їх видалити. Це не спільна база для команди.

## Smart-метрики Entropy

Це власна оцінка довіри, а не гарантоване визначення людей і ботів.

Для оціненого акаунта зберігаються вага довіри `0`, `0.5` або `1`, причина, докази та дата перевірки. Неперевірений акаунт залишається в стані «не оцінено» й не прирівнюється до нульової довіри. Платна верифікація та велика аудиторія самі по собі не є доказом автентичності.

`smart_followers` — сума відомих ваг довіри серед підтверджених підписників автора. Повнота перевірки зберігається окремо. Часткову вибірку не екстраполюємо на всю аудиторію.

`smart_engagement` — сума ваг унікальних зовнішніх акаунтів, які залишили змістовне цитування або відповідь на враховані роботи автора. Один акаунт дає максимум один smart-внесок на кріейтора за обраний місяць. Повторні коментарі, власні взаємодії автора та виключені пости не множать цей показник. Змістовна критика може бути зарахована.

У початковому знімку немає оцінених акаунтів, підтверджених зв’язків підписки чи учасників взаємодій. Позначки повноти smart-даних встановлені в `false`.

## Score на основі Zama

Референс — надана користувачем формула Zama v0.1. Для Entropy явно прийняті такі уточнення:

1. Для арифметики ER використовуємо частку `(likes + reposts + quotes) / impressions`; відсоток — це частка, помножена на 100.
2. `ENG_raw` інтерпретується як зважений `ENG`.
3. `log` у складовій `QE` — натуральний логарифм.
4. За нульового `EngObs` встановлюється `Clamp = 1`, щоб уникнути ділення `0 / 0`.
5. ER понад 20% дає статус **«На перевірці»** та попередній результат, а не автоматичну дискваліфікацію чи бан.
6. Відповіді включені у власне визначення smart engagement Entropy. Звичайний `ENG` зберігає лайки, репости й цитування.

Тому методика не називається точною копією Zama. Обмеження `SENG`, масштабування охоплення, бонус за постинг і штраф за ER понад 10% за менш ніж 50 000 показів збережені у Score.

Менше двох постів або відсутність додатних показів означають невідповідність умовам участі. Невідомі обов’язкові метрики означають неповні дані, а не нульовий бал. За початковим знімком повний Score визначити неможливо: відсутні точні API-репости, цитування, кількість підписників та smart-дані.

CPM-ліміт і розподіл грошових винагород не входять до цього рейтингового прототипу.

## Що ще не підключено

- Живе джерело X і фоновий збір, який працює із закритим кабінетом.
- Спільна серверна база та доступ команди проєкту.
- Захищена особиста сторінка кріейтора з перевіркою його акаунта.

API-ключі не слід додавати в `seed.json`, HTML або файли, що потрапляють у браузер. Підключення X потребуватиме окремого серверного зберігання доступу та перевірки дозволів.


## Передача та перевірка

- `scoring.js` — версія формули та власні smart-метрики Entropy.
- `model.js` — агрегація, перевірка даних, рішення й авторський перегляд без внутрішніх нотаток.
- `app.js` — локальний кабінет і збереження в браузері.
- `seed.json` — початкова публічна дослідницька вибірка, без секретів.
- `build.mjs` — збірка самостійного HTML; `serve.mjs` — лише локальний перегляд.

Запуск перевірок: `node --test scoring.test.mjs model.test.mjs twitterapi.test.mjs collect-twitterapi.test.mjs`. Перевірки охоплюють формулу, модерацію, міграцію ідентичностей, адаптер і обмежений ручний збір; API-відповіді для них змодельовані. У браузері перевірені зміна періоду й сортування, виключення та повернення поста, збереження бану після перезавантаження та повторного імпорту, відсутність внутрішньої нотатки в авторському прев’ю, відхилення пошкодженої резервної копії.

Імпорт підготовленого набору даних зберігає ручні рішення за ID. Імпорт файлу з `kind: entropy-backup` відновлює і дані, і рішення з резервної копії. Під час переходу з `sample:<handle>` на справжній X User ID рішення переносяться лише за спільним точним ID поста. Збігу handle недостатньо; суперечливий перехід відхиляється до зміни поточного стану.

Поле `workId`, якщо надане, об’єднує частини треду для кількості робіт і бонусу регулярності. Без даних про групування потрібна ручна перевірка. Покази й реакції відображаються за включеними постами; унікальне людське охоплення не заявляється.

Позначка повноти списку підписників не приймається без узгодженості з кількістю отриманих підтверджених підписників. Smart-метрики показують пропуски окремо: невідоме не перетворюється на нуль.

У браузерній версії немає API-ключа, зовнішніх запитів, фонових завдань, публікації, спільного серверного сховища чи авторизації для кріейторів. Окремий серверний збирач може виконати запити лише після явного ручного запуску з налаштованим ключем; у цій сесії реальні запити до API не виконувалися. Авторський екран — приватне прев’ю та окремий експорт статусу.


## Обраний API-провайдер

Підготовлено `twitterapi.mjs` і `collect-twitterapi.mjs` для twitterapi.io. Докладні інструкції, межі метрик та офіційні джерела: [TWITTERAPI.md](TWITTERAPI.md). Вони включені до вихідного архіву, але не вбудовані у браузерний HTML. Автоматичний розклад ще не реалізовано.

Перевірка поточної збірки: **57 автоматичних перевірок пройшли**. Під час цих перевірок справжній API не викликався. Реєстр доказів ідентичності зберігає зв’язок автора з відомими постами навіть після тимчасової відсутності автора в імпорті; до авторського експорту цей внутрішній реєстр не входить.
